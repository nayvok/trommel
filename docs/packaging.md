# Packaging status

| Format | v1 status | Why |
|---|---|---|
| `.deb` | **GitHub Releases** | Full host access for `nvidia-smi`, polkit helper, systemd user unit, GSettings and the GNOME extension. No apt repository/PPA. |
| `.rpm` | Spec template, not released | Needs a Fedora/openSUSE test pass; paths and dependencies differ. |
| AppImage | Deferred | Read-only mount cannot install the daemon, polkit helper or extension; a portable tarball + installer is the better fallback. |
| Flatpak | Deferred | Sandbox lacks `/dev/nvidia*` and `/proc/driver/nvidia`, cannot use host `nvidia-smi`, the polkit helper, systemd user unit or install the extension, and downloads miner binaries at runtime. A GUI-only Flatpak is a different product. |

## GitHub Releases (the only distribution channel)

There is **no apt repository and no PPA**. Each release is a `.deb` attached to
a GitHub Release:

```bash
./scripts/release-bundle.sh
# dist/release/trommel_0.4.1_amd64.deb
# dist/release/trommel_amd64.deb          (stable latest URL)
# dist/release/*.sha256
# dist/release/trommel-install.sh
```

The tag workflow (`.github/workflows/release.yml`) runs the tests, builds the
bundle and publishes these assets with `softprops/action-gh-release`. Users
download the `.deb` from
<https://github.com/nayvok/trommel/releases/latest> and install it with
`sudo apt install ./trommel_amd64.deb`, or run `trommel-install.sh`, which
verifies the SHA-256 first. Upgrades are new release downloads;
`sudo apt remove trommel` removes the package and keeps the user config.

Layout: `/usr/bin/{trommel,trommeld}`, `/usr/libexec/trommel/trommel-oc`,
polkit action + generic rule + a per-user rule generated by `postinst` for
`SUDO_USER`, systemd user units, D-Bus service, desktop/metainfo/icons,
GSettings schema and the extension under `/usr/share/gnome-shell/extensions/`.

`postinst` compiles schemas, refreshes desktop/icon caches and writes
`/etc/polkit-1/rules.d/50-trommel.rules` for the installing user, so GPU tuning
does not prompt from the user service. `postrm` removes that generated rule.
The package intentionally does **not** enable the user service or the extension:
D-Bus activation starts the daemon on demand, and the first app launch offers
the extension.

The package depends on GTK4/libadwaita/glib, `libglib2.0-bin`, `pkexec`/polkit,
user D-Bus and systemd; NVIDIA and GNOME Shell are recommendations. It is
built/tested on Ubuntu 26.04; `scripts/test-deb.sh` validates the layout and a
Docker Ubuntu 26.04 install can be used for a disposable check.

## Flatpak notes for the future

A self-hosted Flatpak would need `--device=all`, broad host filesystem access,
`flatpak-spawn --host` for `nvidia-smi` and a host-side helper installation.
That defeats the sandbox and is not Flathub-eligible. Revisit only with a proper
host bridge/portal design.
