# ADR 0008: Desktop tray in the daemon

Status: accepted for the basic tray; the follow-up (show/hide, start minimised,
dynamic icon, submenus) is tracked in [roadmap.md](../roadmap.md).

## Context

Trommel is a background manager: `trommeld` owns the miner and the GPU state,
while the GTK app is a short-lived client. Users asked for a tray icon with
Start/Stop and a full Quit, and for a menu that looks like a native panel menu
(Happ/Telegram style) on both GNOME and KDE.

The tray must be present without an open window, must survive a GUI crash and
must be able to stop mining. A tray hosted by the GTK process would disappear
when the window closes and would make the GUI part of the mining lifecycle,
which contradicts the existing “a GUI crash is a no-op” rule.

## Decision

Host a freedesktop **StatusNotifierItem** in `trommeld` using `ksni` (pure Rust,
StatusNotifierItem plus DBusMenu; adds zbus 5 alongside the daemon's zbus 6 but
no shared-library dependency). The menu contains a disabled status header,
Start/Stop mining, Show window and Quit:

- Start/Stop goes through `Engine::tray_toggle`, the same supervisor and busy
  guard as the D-Bus `Toggle()` method.
- Show window uses `dbus::launch_gui()`, the same `gtk-launch`/`trommel gui`
  path as `OpenApp()`.
- Quit uses a `tokio::sync::Notify` handled by the main select. Before the
  graceful stop it emits the additive `QuitRequested` D-Bus signal, which a
  running GUI listens for in a small separate thread; the normal shutdown then
  stops only Trommel's miner, restores the snapshot, disarms the guard and
  exits. Losing the daemon without the signal does not close the GUI.

The panel icon is the symbolic icon by default (`behavior.tray_monochrome =
true`); the colour icon is an explicit opt-out. Both are installed in hicolor,
and the setting is live (no miner restart). `TROMMEL_NO_TRAY=1` disables the tray
for tests and screenshots.

`trommeld.service` is enabled for the installing user on first package install
(and by `install.sh`), so the tray exists after login by default. **Start
Trommel at login** in Settings writes the same systemd unit state; **Start
mining at login** remains the separate `trommel-autostart.service`.

## Consequences

- The tray exists exactly while the daemon runs, independent of the window.
- KDE Plasma supports the protocol natively. GNOME Shell needs the AppIndicator
  extension (`ubuntu-appindicators` on Ubuntu); without a StatusNotifierItem
  host the tray is absent and the app keeps working. The package does not
  install or touch shell extensions, preserving ADR 0004.
- Windows is not supported: SNI is a freedesktop/Linux protocol and the rest of
  the app is Linux-only today. A Windows port would need a separate platform
  backend and a new ADR.
- The daemon gains a desktop-integration responsibility in addition to
  notifications. It still has no GTK dependency.
- The `QuitRequested` signal is advisory and additive; older clients ignore it.
  A missed signal leaves the window showing the existing service-down state,
  which is the documented fallback.
- The first tray iteration deliberately has no show/hide switch, start-minimised
  mode, dynamic status icon or submenus; those need a follow-up branch.
