# Internationalization

Trommel ships English source strings and Russian translations. There is no
gettext catalogue yet; a small runtime helper keeps the UI bilingual today and
is isolated so it can be replaced later without touching call sites.

## Rust

```rust
use trommel_core::i18n::{tr, tr_ref, set_language, Language};

let text = tr("Start", "Запустить");
let static_label = tr_ref("System", "Системная");
set_language(Language::Ru);
```

- `Language::{System, En, Ru}`; `System` resolves `LANGUAGE`, `LANG` or `LC_ALL`
  and falls back to English unless the value starts with `ru`.
- `set_language` updates a process-global `AtomicU8`; the GUI calls it at start
  and the daemon calls it when an applied config changes the language.
- `tr(en, ru)` returns `String` (safe for `format!` interpolation);
  `tr_ref(en, ru)` borrows a `'static` translation.
- The setting lives in `behavior.language`; changing it takes effect after an
  app restart (the Settings row says so). The daemon applies the new language as
  part of `ApplyConfig` so notifications/status strings follow.
- Dynamic messages build one full sentence per language; never concatenate
  translated fragments.

## Catalogue

`miners.toml`, `coins.toml` and `pools.toml` carry `*_en`/`*_ru` fields
(descriptions, option labels/help, notes). Accessor helpers on the types choose
the language (`short_description()`, `label()`, `help()`, `description()`,
`note()`). Both fields are required; there is no automatic English fallback for
an empty translation, so add both.

## Current state and known gaps

- The GUI, desktop notifications and daemon messages are bilingual.
- The CLI **human** output is Russian-only; `--json` output is language-neutral
  and is the stable interface. Do not scrape human CLI output.
- Some daemon log lines are Russian (`log_line` messages); the log is diagnostic,
  not a translated surface.
- The metainfo/desktop files contain English and Russian descriptions.
- There is no `.pot`/`.po` in the repository yet; the planned gettext catalogue
  will live in `po/`.

## Gettext migration plan

The helper is intentionally a single indirection:

1. Add `gettext-rs` with `gettext-system` (glibc) to avoid static LGPL gettext.
2. Wrap strings with `gettext`/`ngettext`; keep the same English source strings.
3. Extract Rust strings with `xtr`.
4. Compile `po/ru.po` with `msgfmt`; install to
   `/usr/share/locale/ru/LC_MESSAGES/trommel.mo`.
5. Add `translation type="gettext"` to the metainfo.
6. Never commit `.mo` files; keep `.pot`/`.po` in git. Do not break `tr(en, ru)`
   call sites in the same change — migrate incrementally.

Until then, any new user-visible string must be added in both languages.
